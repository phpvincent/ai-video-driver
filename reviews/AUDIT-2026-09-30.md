## 一、P0：开工前必须修（6 项）

### P0-1 项目不是 git 仓库，G3 门禁和全部回滚方案落空
- 事实：`git rev-parse` 返回 `not a git repository`
- 影响：宪法 §3 G3 "重点审查 diff"无 diff 可审；SPEC-01~06 的回滚全部写的是 `git revert`
- 修复：SPEC-01 子任务 1.1 首步 `git init`；**每个子任务验收通过即 commit**，每个 spec 验收通过打 tag（`spec-01-accepted`）；宪法 G3 明确以 `git diff <上一 tag>..HEAD` 为审查对象

### P0-2 父 agent 物理上无法执行一半的验收项
- 事实：宪法 §3 规定父 agent "亲自执行验收、不信任汇报"；但 SPEC-02~06 大量验收项是联调：需要已登录 B 站的真实浏览器、DevTools Network 面板、人工秒表、肉眼判断浮层遮挡。agent 做不到这些
- 影响：要么这些条目永远无法验收，要么被悄悄降级成"信任汇报"，宪法铁律名存实亡
- 修复：验收项分三级并逐条标注
  - **[自动]** 父 agent 直接运行：build / 单测 / 红线检查脚本 / fixture 回放测试
  - **[半自动]** 父 agent 用浏览器自动化加载扩展执行（不需要 B 站登录的场景）
  - **[人工]** 由用户按父 agent 生成的检查清单操作并回报结果（需要登录、真实观感、性能手感）
  - 宪法增补：**人工项由用户作最终验收人**；父 agent 负责生成清单、汇总结果、判定门禁

### P0-3 Chrome 不允许 Side Panel 自动打开
- 事实：`chrome.sidePanel.open()` 只能在用户手势（点击）响应中调用；页面加载时无法自动弹出
- 影响：SPEC-01 A3 "打开 B 站视频页，Side Panel 自动打开"这一条技术上不可能通过
- 修复：改为"视频页自动为该 tab 启用 panel 并显示当前 videoId；用户点击工具栏图标**一次点击**打开"；可加页面内注入的悬浮按钮作为第二入口

### P0-4 划词的"字"没有着落：Panel 里没有字幕视图
- 事实：Panel 只有大纲/导图/问答三个 Tab；SPEC-05 的划词依赖 `content/selection.ts` 在 B 站页面上选字幕
- 影响：B 站 CC 字幕渲染在播放器浮层上，逐句闪现、随播放消失、与播放器手势冲突，基本选不中；MVP 核心交互"遇到不懂的名词划一下"会直接落空
- 修复：Panel 新增 **字幕 Tab**（全文字幕列表，跟随播放高亮当前句，点击句子跳播）；划词在 Panel 内完成，完全受控、不碰播放器；`content/selection.ts` 降为可选增强。该 Tab 放入 SPEC-02（字幕产物的自然展示）

### P0-5 长任务宿主选错：pipeline 放在 Service Worker 里
- 事实：SPEC-03 把 map-reduce 放在 `background/`（Service Worker）；MV3 SW 空闲约 30 秒被回收，上轮审计为此加了"fetch 保活 + 断点续跑"
- 影响：保活是在对抗平台机制，脆弱且难测
- 修复：**pipeline 改在 Side Panel 页面内执行**（用户看视频时 panel 本来就开着，是文档上下文，没有 30 秒限制）；SW 退化为薄路由层。SPEC-03 A6 已要求 pipeline 是无 chrome.* 依赖的纯函数，迁移零成本。分块级落盘保留，用于"关闭 panel 后重开续跑"
- 连带：API key 只在 panel/background 使用，**永不进入 content script**（content script 与 B 站页面同处一个 DOM 环境，是最不可信的一层）→ 新增为红线 10

## 二、P1：对应 spec 开工前修（7 项）

### P1-1 MVP 没有"验证成功"的判定标准（产品视角最大缺口）
- 事实：罗盘 §0 定位"v0.1 验证模式是否可行"，但全部文档没有定义什么叫"可行"
- 影响：SPEC-06 验收完只能证明"功能能用"，回答不了"这个模式值不值得继续投入"
- 修复：新增 **SPEC-07 · MVP 验证期**（SPEC-06 后执行，1~2 周真实使用），预设判定指标，例如：
  - 真实学习视频 ≥ 10 个；字幕一级通道命中率（承接 SPEC-02 A3c）
  - 大纲跳转使用次数 / 视频；划词 + 区间提问次数 / 视频
  - 主观：看视频时"切出去搜索"的次数是否明显下降（每视频结束一问打分）
  - 继续 / 调整 / 放弃三档判定阈值写在 spec 里，验证结束由用户拍板
- 顺带：qaHistory 与使用埋点本来就在本地，指标可直接统计，不需要额外采集

### P1-2 大纲质量没有验收，只验了速度和格式
- 事实：SPEC-03 验收 P90 耗时、Schema 通过率、吸附精度，但没有一条衡量"章节划分合不合理"
- 修复：固定 3 个黄金样例视频（取自 fixtures），用户对首版大纲按 3 项打分（章节边界合理 / 标题准确 / 无遗漏重要段落），作为 prompt 迭代的基线；prompt 改版必须不低于基线

### P1-3 "双维护 + diff 校验"不可执行
- 事实：红线 6 要求 `src/prompts/*.ts` 与 `.agents/skills/*/SKILL.md` 同源双维护，验收写"diff 校验"；但一个是 TS 代码、一个是 Markdown 说明书，格式不同，字面 diff 没有意义
- 修复：改为**单一事实源**——运行时 prompt 正文放 `src/prompts/*.md`（构建时以文本导入）；SKILL.md 的 `references/` 直接链接该文件而不复制。`npm run check:prompts` 校验链接存在、SKILL 声明的规则关键字在 prompt 中都出现。红线 6 随之改写为"prompt 单一事实源，禁止复制"

### P1-4 红线无检查手段
- 事实：九条红线只有描述，验收时靠人肉审 diff
- 修复：每条红线绑定检查方式，汇总为 `npm run check:redlines`：
  - 红线 3 → 编译器单测断言上下文不含全量字幕
  - 红线 5 → 所有解析器单测断言输出含 startMs/endMs
  - 红线 9 → grep 规则：`sk-` 类密钥、`api.bilibili.com` 等 URL 只允许出现在 `src/config/` 常量文件
  - 红线 10（新增）→ grep 规则：content/ 目录禁止引用 modelConfig/apiKey
  - 其余红线 → 指定对应单测文件名

### P1-5 测试策略缺"离线可复现"
- 事实：SPEC-02/03 联调依赖真实 B 站接口与真实模型，结果随网络、登录态、模型抖动变化，父 agent 无法稳定复跑
- 修复：测试框架定为 vitest；SPEC-02 首次联调时把 5 个 fixture 视频的真实接口响应**录制**为 `tests/fixtures/*.json`，模型调用用录制响应回放。这样 [自动] 级验收可离线、确定性地复跑，也直接支撑 P0-2

### P1-6 共享文件的并行冲突与契约先行
- 事实：SPEC-04 ∥ SPEC-05 并行，两者都要改 `types.ts`、消息协议（background 路由）、panel 共享状态
- 修复：
  - SPEC-01 增交付物 **共享契约**：`src/types.ts`（Cue/Section/FetchResult/QaRecord 全量类型）+ `src/messages.ts`（消息协议枚举），按 TECH-DESIGN §4 一次性定义
  - 宪法 §4 增补：共享契约文件**只能由父 agent 修改**，子 agent 需要变更时提需求；并行 spec 各自只拥有自己的目录

### P1-7 子 agent 派发包没有标准格式
- 事实：子 agent 是独立上下文，看不到本次对话；宪法只写"按 spec 执行"
- 修复：新增 `specs/_DISPATCH_TEMPLATE.md`，每次派发必须包含：spec 路径与子任务编号、宪法红线全文、相关 TECH-DESIGN 章节原文摘录、**允许修改的文件清单**、禁止触碰的文件、DoD、回报格式（改动文件列表 + 自测命令与输出）。同时增补 `specs/_SPEC_TEMPLATE.md` 统一 spec 结构
