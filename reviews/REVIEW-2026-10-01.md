## 3. 做得好的地方（应保持）

1. **纯函数 + 依赖注入**：`core/` 零 `chrome.*` 依赖，963 例测试 2 秒跑完，不需要 jsdom 和网络。这是后续一切重构的底气。
2. **红线脚本化**：R9（禁止硬编码端点和密钥）、R10（content 不得接触密钥）是可执行规则，而不是文档里的一句话。
3. **失败降级的完整性**：概念图降级为术语图、抽帧规划降级为公式、截断 JSON 自愈、检索失败静默——没有一处因为模型出错而白屏。
4. **"代码掌握最终解释权"**：模型给的时间点一律吸附到真实字幕，输出一律过 Zod 校验。这是 LLM 应用里最容易被忽视、也最重要的一条。
5. **可观测性**：LLM 日志把"模型为什么失败"从猜测变成了证据——本轮的截断、帧数不足、上限冲突都是靠日志定位的。

## 4. 需要改进的地方

### P0（阻断核心价值，先修）

| # | 问题 | 位置 | 修法 |
|---|---|---|---|
| P0-1 | **登录态字幕通道存疑**：请求从扩展页发出，SESSDATA 是 SameSite=Lax，跨站 `credentials:'include'` 大概率不带 cookie → 一级通道恒降级为手动粘贴 | `providers/bilibili.ts:66`、`panel/subtitleLoader.ts` | 先用已登录 Chrome 实测一次；若确认不带，把三次 B 站请求下沉到 content script（同源自动带 cookie），结果经消息回传 |
| P0-2 | **笔记回链全空**：`meta = { ...video, cid: 0, url: '' }`，`playbackUrl()` 返回空串 → Obsidian 里所有时间戳都不可点 | `App.tsx:400` | content 上报视频信息时带上 `location.href` 与 cid；`playbackUrl` 在 url 为空时回落 `https://www.bilibili.com/video/{bvid}?p={page}&t={sec}` |
| P0-3 | **自定义端点被 CORS 拦截**：manifest 只预置了几个域名，全仓没有 `permissions.request` | `manifest.json`、设置页保存逻辑 | 加 `optional_host_permissions: ["https://*/*"]`，保存模型配置时按 baseUrl 申请 |

### P1（功能闭环缺口）

| # | 问题 | 说明 |
|---|---|---|
| P1-1 | 问答回答里的 `[mm:ss]` 永不渲染成可跳按钮 | `<ChatTab>` 没传 `cues`，吸附函数拿到空数组 |
| P1-2 | 术语去重传空表 | 同一术语会重复生成卡片 |
| P1-3 | 大纲增量进度钩子未接 UI | 长视频生成期间只能干等 |
| P1-4 | **问答无多轮记忆** | 每次提问都是独立请求，"那第二步呢？"这类追问模型看不懂。学习场景追问极常见，这是体验上最大的短板 |
| P1-5 | **无流式输出** | 打字机效果是拿到完整回答后再"假打"。首字延迟 = 整个回答的生成时间（带图时 5~15 秒） |
| P1-6 | traces store 建了但从未写入 | 设计文档里的 PipelineTrace 实际不存在；LLM 日志部分替代了它 |
| P1-7 | 治理脱节 | SPEC-03~06 未验收、无 tag、宪法状态过期 |

### P2（质量与维护）

- token 估算用 `字符数/2`，对中文低估约 2 倍 → 预算熔断偏松（`outline.ts:151`、`compiler.ts:56`）
- 只认 BV 号，不支持 av 号 / b23.tv 短链 / 番剧页
- `ChatTab.tsx` 已近 900 行，渲染、状态、上传、历史恢复混在一起，需要拆分
- 两套"帧说明"并存（`describeImages` 旧的时间列表 + 新的 `caption`），问答路径两者都会输出，信息重复
- 抽帧会暂停视频十几秒（40 帧时），用户没有进度提示，也不能取消
- 没有端到端测试：所有 `chrome.*` 接线、canvas、真实模型响应都没有自动化覆盖

### 关于抽帧与多模态的专业意见

这部分本轮投入很大，效果也最不确定，单独说：

1. **它超出了 v0.1 的范围**。路线图把"结构感知抽帧"标为 ★、v0.1.x 评估；v0.1 的验证假设里根本没有画面。现在它已经是整个系统里最复杂的子系统（候选、规划、护栏、去重、配对、预算分段）。
2. **收益尚未被证明**。我们没有任何对照数据说明"带 40 帧的导图"比"纯字幕导图"更好。多模态请求贵 3~10 倍、慢 2~5 倍。
3. **建议**：SPEC-07 期间把抽帧当成一个**实验变量**，而不是默认开启——每个视频随机选择开或关，报告里对比两组的"导图跳转次数"和主观评分。用数据决定它的去留。

## 5. 进化空间（按价值排序）

| 方向 | 为什么值得做 | 成本 |
|---|---|---|
| **问答多轮记忆** | 追问是学习的主要形态；现在每问都是冷启动 | 低：把最近 3~5 轮 Q/A 摘要拼进上下文 |
| **流式输出** | 首字延迟从 10 秒降到 1 秒，体验提升最明显的一项 | 中：modelClient 改 SSE，JSON 输出需改成"先流正文，后补结构化字段" |
| **薄弱章节标记**（路线图 ★★★） | 问得最多的章节 = 没听懂的地方，直接闭合"学习 → 复习"环 | 低：qaHistory 已有数据 |
| **拍题作答 → 错题本** | 本轮的上传图片功能，天然可以沉淀为 Obsidian 错题卡（题图 + 解析 + 关联章节） | 低 |
| **章节级缓存复用** | 重生成大纲只改了一章时，导图、问答的缓存可以局部保留 | 中 |
| **YouTube provider** | timedtext 接口成熟；B 站之外最大的学习视频来源 | 中 |
| **ASR 桥接**（v0.2） | 无字幕视频是最大的内容盲区 | 高：需本地后端 |
